<objective>
Implementar Liquibase Maven Plugin (Option B) para permitir al usuario sincronizar manualmente la base de datos QA remota sin arrancar la aplicación Spring Boot, y añadir el perfil Spring `qa` para cuando sí se ejecute la app contra QA.

**Purpose:** Hoy las migraciones Liquibase sólo corren al arrancar Spring Boot (vía `spring.liquibase.change-log`). Para QA queremos un canal manual y explícito que el usuario dispare desde su máquina sin levantar el servidor, evitando además acoplar el arranque de la app al estado migratorio del entorno remoto.

**Output:**
- `liquibase-maven-plugin` configurado en `pom.xml` con dos perfiles Maven: `dev` (local, igual a `.env`) y `qa` (remoto).
- `application-qa.properties` para que `--spring.profiles.active=qa` levante la app contra QA con env vars `${QA_DB_URL}`, `${QA_DB_USERNAME}`, `${QA_DB_PASSWORD}`.
- `liquibase-*.properties` files con credenciales (gitignored) + un `.example` documentado y committed.
- `.gitignore` actualizado para excluir `liquibase-*.properties` (excepto el `.example`).
</objective>

<task type="auto">
  <name>Task 1: Add liquibase-maven-plugin with dev/qa Maven profiles to pom.xml</name>
  <files>prestamil-backend/pom.xml</files>
  <action>
Modify `prestamil-backend/pom.xml` to add the Liquibase Maven plugin under two Maven profiles. DO NOT add the plugin to the default `<build><plugins>` block — it must only execute when a profile is activated, so accidental runs against the wrong DB are impossible.

Steps:

1. Add a `<liquibase-maven-plugin.version>` property in `<properties>`:
   ```xml
   <liquibase-maven-plugin.version>4.27.0</liquibase-maven-plugin.version>
   ```
   Version 4.27.0 is chosen to match the Liquibase 4.x line bundled with Spring Boot 3.2.5 (`liquibase-core` managed by Boot BOM). DO NOT use 5.x — incompatible with Boot 3.2.5.

2. After the closing `</build>` tag, add a `<profiles>` block with two profiles:

   ```xml
   <profiles>
       <profile>
           <id>dev</id>
           <build>
               <plugins>
                   <plugin>
                       <groupId>org.liquibase</groupId>
                       <artifactId>liquibase-maven-plugin</artifactId>
                       <version>${liquibase-maven-plugin.version}</version>
                       <configuration>
                           <propertyFile>liquibase-dev.properties</propertyFile>
                       </configuration>
                       <dependencies>
                           <dependency>
                               <groupId>org.mariadb.jdbc</groupId>
                               <artifactId>mariadb-java-client</artifactId>
                           </dependency>
                       </dependencies>
                   </plugin>
               </plugins>
           </build>
       </profile>
       <profile>
           <id>qa</id>
           <build>
               <plugins>
                   <plugin>
                       <groupId>org.liquibase</groupId>
                       <artifactId>liquibase-maven-plugin</artifactId>
                       <version>${liquibase-maven-plugin.version}</version>
                       <configuration>
                           <propertyFile>liquibase-qa.properties</propertyFile>
                       </configuration>
                       <dependencies>
                           <dependency>
                               <groupId>org.mariadb.jdbc</groupId>
                               <artifactId>mariadb-java-client</artifactId>
                           </dependency>
                       </dependencies>
                   </plugin>
               </plugins>
           </build>
       </profile>
   </profiles>
   ```

Notes / things to AVOID:
- DO NOT hardcode `url`, `username`, or `password` inside `pom.xml` — `pom.xml` is committed to git. All credentials live in the external `liquibase-*.properties` files (gitignored).
- DO NOT add `<executions>` with a default phase. The plugin should ONLY run when the user explicitly invokes `mvn liquibase:update -Pdev` or `mvn liquibase:update -Pqa`. An execution bound to `process-resources` would run on every `mvn compile/install`, which is dangerous for QA.
- The `<propertyFile>` path is resolved relative to the project basedir (`prestamil-backend/`), so `liquibase-dev.properties` lives at `prestamil-backend/liquibase-dev.properties`.
  </action>

**A. `prestamil-backend/liquibase-dev.properties` (NOT committed):**

```properties
# Liquibase Maven Plugin - local dev DB
# Run with: mvn liquibase:update -Pdev
# Mirrors the dev DB referenced by .env (DB_URL / DB_USERNAME / DB_PASSWORD).
# Edit these values to match your local MariaDB.
```

The exact `url`/`username`/`password` should match what the developer has in `.env` for `DB_URL`/`DB_USERNAME`/`DB_PASSWORD`. Use placeholder `CHANGE_ME` for password; user will fill it locally.

**B. `prestamil-backend/liquibase-qa.properties` (NOT committed):**

```properties
# Liquibase Maven Plugin - QA remote DB
# Run with: mvn liquibase:update -Pqa
# WARNING: This writes to the QA database. Verify changelog locally first.

changeLogFile=src/main/resources/db/changelog/db.changelog-master.xml
driver=org.mariadb.jdbc.Driver
url=jdbc:mariadb://QA_HOST:3306/prestamil_qa
username=CHANGE_ME
password=CHANGE_ME
```

**C. `prestamil-backend/liquibase-qa.properties.example` (COMMITTED — template):**

Same content as (B) but with safe placeholders and an extra header comment:

```properties
# Template for liquibase-qa.properties
# Copy to liquibase-qa.properties and fill in the QA credentials.
# DO NOT commit liquibase-qa.properties.

changeLogFile=src/main/resources/db/changelog/db.changelog-master.xml
driver=org.mariadb.jdbc.Driver
url=jdbc:mariadb://YOUR_QA_HOST:3306/YOUR_QA_DB
username=YOUR_QA_USER
password=YOUR_QA_PASSWORD
```

**D. `prestamil-backend/src/main/resources/application-qa.properties` (COMMITTED):**

Mirrors the structure of `application-prod.properties` but uses QA-scoped env vars and keeps QA-appropriate settings (SQL logging useful for QA debugging, cookie config like dev since QA may not be HTTPS yet — DO NOT enable `secure=true` unless QA is behind HTTPS).

```properties
# ── QA profile ───────────────────────────────────────────────────────────────
# Active with: SPRING_PROFILES_ACTIVE=qa
# Env vars required: QA_DB_URL, QA_DB_USERNAME, QA_DB_PASSWORD, ENCRYPTION_SECRET
# Missing vars cause startup failure (fail-fast).

spring.datasource.url=${QA_DB_URL}
spring.datasource.username=${QA_DB_USERNAME}
spring.datasource.password=${QA_DB_PASSWORD}

app.encryption.secret=${ENCRYPTION_SECRET}

# Keep SQL visible in QA for diagnosis; turn off in prod.
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true

# IMPORTANT: Manual migration only. Disable Spring's auto-Liquibase in QA so the
# environment is controlled exclusively via `mvn liquibase:update -Pqa`.
spring.liquibase.enabled=false
```

Notes / WHY:
- `spring.liquibase.enabled=false` in QA is deliberate: this entire plan is about MANUAL migration. Leaving it `true` would re-introduce auto-migration on app startup, defeating the purpose.
- The QA env var prefix (`QA_DB_*` vs `DB_*`) lets a developer keep dev and qa credentials side-by-side in shell/env without collision.

**E. `prestamil-backend/.gitignore` — append a new section AFTER the existing `# Environment secrets` block:**

```

liquibase-*.properties
!liquibase-*.properties.example
```

The `!` negation keeps the `.example` template tracked. Place this block at the end of the file.
