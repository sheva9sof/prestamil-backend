```sql
--liquibase formatted sql

--changeset emmanuel:004-fulltext-clientes comment:FULLTEXT index on clientes(nombre, apellido_paterno, apellido_materno) for MATCH/AGAINST queries
ALTER TABLE `clientes`
  ADD FULLTEXT INDEX `ft_clientes_nombre_completo` (`nombre`, `apellido_paterno`, `apellido_materno`);
--rollback ALTER TABLE `clientes` DROP INDEX `ft_clientes_nombre_completo`;
```

Notas de implementación (NO incluir como comentarios SQL, son para el ejecutor):

1. **Nombres de columnas:** Usar `apellido_paterno` y `apellido_materno` (snake_case),
   NO `apellidoPaterno` / `apellidoMaterno`. Verificado contra 001-initial-schema.sql líneas 297-298.

2. **NO añadir índice sobre `telefono`:** la línea 305 de 001-initial-schema.sql ya define
   `UNIQUE KEY \`telefono\` (\`telefono\`)`, que sirve también como índice B-tree.
   Añadir otro generaría warning de duplicado.

3. **NO crear índices sobre `contratos`:** la tabla no existe en el schema actual.
   Si se intenta `ALTER TABLE contratos ADD INDEX ...`, Liquibase fallará con
   "Table 'contratos' doesn't exist" y dejará el changeset en estado inválido.

4. **Engine InnoDB con FULLTEXT:** soportado desde MariaDB 10.0+ (constraint declarada en CLAUDE.md).
   La tabla `clientes` ya es InnoDB (línea 308), por lo que no requiere ALTER ENGINE previo.

5. **Rollback:** la línea `--rollback` permite que `liquibase rollback` revierta el cambio.
   Es un comentario reconocido por Liquibase formatted SQL — no quitar.

6. **Convención de proyecto:** changesets numerados secuencialmente (001, 002, 003, 004).
   El autor `emmanuel` y el comentario en español siguen el patrón de 001-initial-schema.sql.
